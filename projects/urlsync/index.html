URLSync

A self-hosted alternative to Brave Sync — one small VPS, Postgres, and Tailscale, built to practice the parts of cloud infrastructure that don't show up in a tutorial: adopting a server that already exists, and debugging tools that quietly stop working.

URLSync-api → URLSync-infrastructure → iluvi.xyz

The problem

I use Brave across a laptop, an Android tablet, and an iPhone, and wanted saved URLs to follow me across all three. Brave already solves this — Brave Sync is built in, end-to-end encrypted, no account required.

I built this anyway. Not because Brave Sync is lacking, but because a small, real, single-user service is a better way to practice Terraform, Docker, and Postgres than another tutorial project with no actual constraints.

note The best learning projects solve a problem you already have — even when a better tool already exists.

Architecture

One VPS, already running a static site on nginx, adopted into the project rather than replaced. Two containers — FastAPI and Postgres — talk over Docker's internal network only. Every device reaches the app through Tailscale, so there's no public port to secure, patch, or worry about.

note No reverse proxy, no TLS certificates, no open firewall rule for the app itself — Tailscale replaces all three.

Decisions worth explaining

  • Postgres, not SQLite
    SQLite would have been simpler for one user and a handful of URLs. Chose Postgres deliberately — schema, connection strings, backups, and migrations are skills that show up at work; a single file doesn't.
  • Adopted the existing VPS
    The box already ran a static site on nginx. Rather than spin up a second server, I brought the existing one under Terraform with terraform import — a far more common real-world task than provisioning from a blank slate.
  • Two repos, one boundary
    Infrastructure and application code live in separate repositories, so a Terraform apply is never the same action as shipping a code change.
  • Tailscale over a public port
    Single user, no need for the internet to reach this at all. Removes an entire category of firewall and certificate management for free.

    • What actually broke

    The first local build failed with a plain connection-refused error — Postgres hadn't finished starting before FastAPI tried to talk to it, since Compose's depends_on only waits for a container to start, not for the service inside it to be ready. Fixed with a pg_isready healthcheck and a proper condition: service_healthy dependency.

    The second failure was stranger: a KeyError buried inside Docker Compose's own event-watching code. Turned out to be a known, unfixed bug in the old standalone docker-compose (V1) binary talking to a modern Docker Engine — V1 is deprecated and was never updated for the newer event format. Swapped to the maintained Compose V2 plugin and the whole stack came up clean.

    note Neither of these was in a tutorial anywhere. Diagnosing them was most of the actual learning.
